# 강사용 환경 준비와 배포 확인

수강생에게는 저장소를 받은 폴더에서 `start.bat` 또는 `start.command`를 실행하도록 안내합니다. 공통 설치와 모델 선택은 수업 전에 끝냅니다. 시작 도구는 서버 보안 설정이나 계정 권한을 자동으로 변경하지 않습니다.

## 1. 공통 환경 준비

교육용 PC 또는 사용자 네임스페이스를 지원하는 Linux 실행 환경에 Python 3.10 이상, Git, 사내 허용 Codex CLI를 설치합니다. 실제 배포할 CLI 버전을 고정합니다. 현재 점검기는 CLI 0.169.0의 `codex sandbox -P :workspace` 형식을 지원하며, 이전 Linux/macOS CLI의 전용 sandbox 하위 명령도 인식합니다. 지원하지 않는 형식은 준비 실패로 표시합니다.

```bash
git clone https://github.com/legenduck/Architect-Practice-1.git
cd Architect-Practice-1
python3 start.py --prepare --model <강사가_검증한_모델명> --reasoning-effort high
```

Windows에서는 `python3` 대신 `py -3`를 사용합니다. 꺾쇠 괄호 부분은 실제 모델명으로 바꿉니다. 추론 설정도 해당 모델이 지원하고 강사가 검증한 값을 사용합니다.

이 명령은 `.venv`와 패키지를 설치하고 `config.json`, `edit/`, 결과 화면을 준비합니다. 기존 작업 지침과 참가자 번호를 덮어쓰지 않습니다. 모델명과 추론 설정은 명시적으로 지정한 경우만 변경합니다. Python 패키지는 요구사항 파일이 바뀌면 다시 설치하며, 설치 실패는 다음 시작에서 재시도합니다.

`config.json`과 `.venv`는 Git으로 배포되지 않습니다. 각 PC에서 위 준비 명령을 실행하거나 사내 PC 준비 절차에 포함하세요. 다른 OS나 경로로 가상환경 폴더를 복사하는 대신 해당 PC에서 생성합니다. Codex 계정과 Git 인증 파일을 공통 배포물에 포함하지 않습니다.

## 2. 준비 점검이 확인하는 범위

- Python 테스트 도구·린트·타입 검사·Git·Codex 실행 가능 여부
- 지정된 모델 설정의 존재
- 모델을 호출하지 않고 Codex 샌드박스 안에서 파일 읽기·쓰기와 작은 pytest 테스트 실행
- 수강생 시작 시 본인 Codex 로그인 상태
- 참가자 브랜치·Git 이름과 이메일·origin 주소
- `git push --dry-run`으로 제출 접속과 권한 문제 확인

공통 준비에서는 개인 로그인을 요구하지 않습니다. 개인 설정까지 끝낸 뒤 `python start.py --check`를 실행하면 전체 준비 상태를 다시 확인할 수 있습니다. 별도 터미널에서 `lab.py`를 사용할 때는 가상환경을 활성화하고 `python lab.py doctor --submission`으로 확인합니다.

점검 명령은 모델 토큰을 사용하지 않습니다. 따라서 **실제 모델 접근 권한, 모델별 추론 옵션 지원, 중앙 채점기의 정상 작동까지 보장하지는 않습니다.** Git dry-run도 이후 권한 변경이나 서버의 실제 수신 훅까지 보장하지 않습니다. 배포 계정으로 기본 지침 실행 → 제출 → 중앙 채점 수신을 최소 한 번 완료해야 합니다.

## 3. 수강생의 첫 실행

수강생별로 GitHub 참여 권한을 부여하고 사내 허용 Git 인증 수단을 설정합니다. Codex 로그인과 GitHub 인증은 별도입니다. 시작 도구는 Codex 로그인이 없으면 로그인 명령을 열고, 참가자 번호와 Git 이름·이메일이 없으면 한 번 입력받습니다. Git 이름과 이메일은 해당 저장소에만 저장합니다.

수강생의 시작 파일이 준비 오류 없이 실습 메뉴를 여는 것을 확인합니다. 이후에는 같은 시작 파일로 메뉴에 들어갈 수 있습니다. 오류로 중단해도 지침·실행 기록·기존 설정은 유지합니다.

## 4. 환경 오류 대응

`bwrap: No permissions to create a new namespace` 또는 샌드박스 파일시스템 격리 오류가 나면 해당 서버에서는 과제 실행을 시작하지 않습니다. 관리자에게 실행 환경의 namespace·AppArmor·컨테이너 정책 지원을 확인하거나, 준비 점검이 통과하는 교육용 환경으로 이동합니다. 시작 도구가 격리를 끄거나 시스템 설정을 변경하지는 않습니다.

Git 인증 또는 쓰기 권한 오류는 저장소 참여 권한과 사내 Git 인증 절차를 확인합니다. 모델 실행 전 점검에서 발견되면 새 과제 실행 폴더나 제출 커밋을 만들지 않습니다. 실행 이후 네트워크가 끊긴 경우에는 실행 기록을 보존하고 결과 화면에 제출 실패를 표시합니다.

## 5. 실행 기록과 비교 조건

CLI가 정상 종료했더라도 완료 이벤트가 없거나 소스가 초기 상태 그대로이면 자동 제출하지 않습니다. 소스 변경은 제출 가능한 최소 조건이며 기능 정확성은 중앙 채점으로 판단합니다. 실패·시간 초과에도 확인 가능한 사용량과 로그는 보존합니다.

모델명·프로필명·명시적인 추론 설정·CLI 버전·초기 코드·과제 요청문·테스트 도구를 실행 조건에 기록합니다. 전역 Codex 지침, 프로필의 실제 내용, 활성 도구까지 전부 고정하는 기능은 아니므로 교육용 PC의 공통 설정을 별도로 통일해야 합니다. `reasoning_effort: null`은 CLI 설정을 따르므로 강사가 명시적으로 설정하는 것을 권장합니다.

회귀 테스트는 로컬 대체 CLI와 임시 Git 저장소를 사용합니다. `python -m unittest discover -s tests_lab -v`로 실행합니다. 서버 샌드박스가 동작하는 환경에서의 실제 모델 실행과 Windows/macOS 시작 파일은 배포 전 별도로 확인합니다.
